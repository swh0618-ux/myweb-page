# 바이브코딩 시대를 맞이하며: AI와 페어 프로그래밍하는 새로운 워크플로우

과거의 개발이 문법과 API 레퍼런스를 검색하고 한 글자씩 타이핑하는 인고의 과정이었다면, 오늘날의 **바이브코딩(Vibe Coding)**은 완전히 다른 차원의 창작 경험을 선사합니다.

<!-- more -->

## 1. 바이브코딩이란 무엇인가?

바이브코딩은 코드를 '손으로 쓰는 것'이 아니라, **'전체 시스템의 감각(Vibe)과 아키텍처 규칙을 제시하고 AI와 실시간으로 핑퐁하며 형태를 빚어나가는 개발 방식'**을 의미합니다.

* **속도의 비약**: 초기 프로토타입에서 첫 배포까지 걸리는 시간이 며칠에서 수십 분으로 단축됩니다.
* **관점의 전환**: 구현 세부사항(Syntax)보다 구조(Architecture), 데이터 흐름(Data Flow), 사용자 경험(UX)에 집중하게 됩니다.

---

## 2. 성공적인 바이브코딩을 위한 3가지 법칙

### ① 규칙 문서화 (Rules as Guardrails)
AI에게 모호하게 명령하지 않고, 프로젝트 루트에 `AGENTS.md`나 규칙 파일을 두어 컨텍스트를 고정합니다. (예: 색상 팔레트, 파일 네이밍 규약, 함수 작성 스타일)

### ② 짧은 피드백 루프 (Rapid Iterations)
에이전트에게 1000줄의 코드를 한 번에 짜게 하지 마십시오.
1. 환경 셋업 → 2. 스켈레톤 작성 → 3. 개별 모듈 구현 → 4. 단위 테스트의 단계로 잘게 쪼개어 검증합니다.

### ③ 자동화 파이프라인 (Automated CI/CD)
코드가 완성되는 즉시 `git push` 하나로 GitHub Actions가 실행되고 GitHub Pages에 빌드 산출물이 배포되는 파이프라인을 가장 먼저 구축해야 합니다.
